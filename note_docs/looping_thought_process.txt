Looping Thought Process Function (Agent Scratchpad):
Purpose:
    Handling multiple step user queries are difficult for low param llms to manage with a single query, especially when the data requires most of the agent's tools and concepts to be fleshed out before creating a concrete step by step plan. Allowing llm to loop through the query allows agents to gather more context from the user query and improve the accuracy of the response. 

Generalized Process:
- query intake: The first part of the process would be to first keep the original copy of the query in memory for querying, and have a work in progress query

- query processing: This part will have the work in progress query be given to the llm where it will generate a response based on the context.

- response validation (loop process): The reponse must be kept by the agent's scratchpad to track the progress of the prompts and state what aspects of the prompt are irrelevant to the original query. This will require another request to the llm to determine what parts of the response are not applicable to the response to the user query.
    - loop end condition: there must be a maximum threshold where the loop process should not pass to avoid constant looping to find the answer.
